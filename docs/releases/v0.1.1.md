# Hegira v0.1.1

Hegira v0.1.1 is a production-correctness and security release for the default
Rust full-stack template. It aligns the minimal PostgreSQL build with its
runtime configuration, fails early on unavailable capabilities, hardens HTTP
trust boundaries, and makes release validation reproducible.

## Highlights

- The default `ssr,db-postgres` image now boots with the committed production
  profile without requiring optional external providers.
- Runtime capability preflight reports every enabled provider that is missing
  from the compiled binary before external dependencies are initialized.
- Cookie-authenticated BFF traffic and Bearer API traffic use distinct CSRF
  policies.
- All unsafe cookie methods require a same-origin browser request.
- Rate-limit client identity uses the TCP peer by default and trusts forwarded
  addresses only from explicitly configured proxy CIDRs.
- CI runs at pull-request and integration boundaries, and the production image
  is exercised against a disposable PostgreSQL database.
- Release validation keeps dependency auditing read-only, isolates destructive
  PostgreSQL tests, and verifies revisioned search outbox payloads against the
  flattened document contract.

## Upgrade And Operator Notes

- The default production binary includes PostgreSQL but not Redis, SMTP, S3,
  Meilisearch, Prometheus, or OTLP. Compile the matching Cargo feature before
  selecting an optional provider in runtime configuration.
- Deployments behind a reverse proxy must configure `security.trusted_proxies`
  with only the networks that connect directly to Hegira. The secure default is
  an empty list; `0.0.0.0/0` and `::/0` are rejected.
- `application.public_url` is the authoritative CSRF origin. Cookie-authenticated
  POST, PUT, PATCH, and DELETE requests must provide a matching Origin, or a
  matching Referer when Origin is absent.
- Bearer API clients remain independent from browser Origin and Referer headers.
- Run the bundled `db_migrator migrate` command as a one-shot step before
  rolling out the application. Do not enable production auto-migration or
  identity seed.
- The release archive stores Leptos assets under `target/site`. Start the binary
  from the extracted bundle directory, or override `LEPTOS_SITE_ROOT` when using
  another layout.

## Release Artifacts

The GitHub Release contains:

- a Linux x86-64 bundle with `hegira`, `db_migrator`, production configuration,
  Leptos assets, documentation, and license;
- a SHA-256 checksum file for the bundle;
- an SPDX JSON software bill of materials.

This release does not create a preview application, public preview URL, or
production deployment.
