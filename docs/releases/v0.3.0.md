# Hegira v0.3.0

Hegira v0.3.0 establishes the implemented framework repository foundation. It
separates reusable framework packages, official module source, canonical
application templates, internal repository tooling, and deployable application
composition while retaining explicit layered architecture and source-only
distribution.

## Highlights

- Application-independent platform packages now own configuration,
  persistence, background work, HTTP policy, Leptos integration,
  observability, runtime lifecycle, capability identity, and test support.
- `modules/identity/` is the canonical source for the official layered Identity
  module: Domain Shared, Domain, Application Contracts, Application, SQLx,
  Axum HTTP, and Leptos adapters.
- Identity HTTP and Leptos adapters contribute explicit routes, transport
  policies, OpenAPI, pages, and navigation. Application composition roots
  select those contributions without runtime discovery.
- `templates/applications/layered/` renders an independent, brand-neutral
  Cargo workspace with application-owned server, web, layered packages,
  configuration, migration composition, and production container files.
- Typed component manifests and the internal `template_renderer` provide
  deterministic, collision-checked, path-safe, and atomic rendering for
  repository validation. They are not a public Hegira CLI.
- The sample Catalog runtime capability has been removed in favor of a neutral
  authenticated dashboard. Historical migration identities and checksums
  remain intact for supported upgrades.
- Repository validation now separates framework, official-module, template,
  generated-application, capability-matrix, and supply-chain responsibilities.

## Generated Application Contract

The canonical rendered application is validated as an independent release
consumer rather than as a member of the framework workspace. Validation covers:

- fresh SQLite and PostgreSQL migration plans;
- upgrades from the supported v0.2.0 database state;
- the native server, tests, WASM hydration, and Cargo-Leptos release output;
- the rendered production image against disposable PostgreSQL;
- readiness, hydration and branding assets, production security headers, and
  unauthenticated Bearer API behavior.

Repository validation temporarily rewrites declared framework dependencies
only inside disposable output. A normal render retains the pinned `v0.3.0` Git
source and contains no maintainer-local paths.

## Upgrade And Maintainer Notes

- Framework source is organized under `crates/`; official Identity source is
  under `modules/identity/`; canonical application source is under
  `templates/applications/layered/`; and internal rendering tooling is under
  `tools/template_renderer/`.
- `apps/hegira/` remains the deployable compatibility host. Existing root-level
  setup and validation commands continue to target that host where documented.
- PostgreSQL and SQLite v0.2.0 upgrade paths are validated. Catalog runtime
  state is retired without rewriting historical migration records.
- Applications must continue to enforce authorization in application services;
  UI permission checks remain presentation behavior only.
- External contributions are not currently accepted unless explicitly
  requested or approved by the maintainer.

## Release And Supply-Chain Contract

- Create the release only from the verified `main` commit with a signed,
  annotated `v0.3.0` tag.
- The release workflow verifies release identity, framework packages, official
  modules, the canonical template, generated applications, and the source SPDX
  SBOM before publication.
- Every workspace package has registry publication disabled. This release does
  not publish framework crates, a CLI package, prebuilt executables, or
  container images.
- Workflow permissions are read-only by default. Only the tag-triggered
  publication job receives `contents: write`, and it depends on every release
  validation gate.
- Keep the release immutable. GitHub's immutable-release contract locks the tag
  and SBOM asset and provides the release attestation.

## Release Artifacts

GitHub provides `.zip` and `.tar.gz` archives of the tagged source. The only
custom release asset is `hegira-v0.3.0.spdx.json`, a source-scoped SPDX SBOM
containing the release tag and commit identity.

This release does not publish an application bundle, deployment artifact,
official container image, preview application, public URL, or GitHub
Environment.
