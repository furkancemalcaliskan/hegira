# Hegira v0.1.2

Hegira v0.1.2 establishes a consistent project identity across the repository
documentation and existing web application surfaces. It introduces the Hegira
philosophy, canonical branding assets, and consistent logo usage without
changing application behavior or runtime contracts.

## Highlights

- The README now presents Hegira with the message "Your destination. A proven
  path." and describes its production-oriented, opinionated approach.
- The Hegira philosophy explains how sensible defaults and explicit
  conventions reduce recurring infrastructure decisions while remaining
  guides, not walls.
- Canonical branding assets now live under a predictable repository structure.
- Temporary letter-based placeholders in the application shell, boot loader,
  and authentication pages now use the Hegira logo.
- The web-public logo is optimized for delivery while the original canonical
  asset is retained for future branding work.
- Manual release validation now requires maintainers to enter the intended
  release ref explicitly instead of inheriting a stale version default.

## Upgrade And Operator Notes

- No database migration is required.
- No configuration changes are required.
- Authentication, authorization, sessions, middleware, runtime roles, and
  deployment behavior are unchanged.
- Existing deployments can upgrade using the same procedure as `v0.1.1`.

## Release Artifacts

The GitHub Release contains:

- a Linux x86-64 bundle with `hegira`, `db_migrator`, production configuration,
  Leptos assets, documentation, and license;
- a SHA-256 checksum file for the bundle;
- an SPDX JSON software bill of materials.

This release does not create a preview application, public preview URL, or
production deployment.
